# Research Contributions & Originality Plan

> **Core Thesis:** Symbolic rules mined from biomedical KGs can measurably improve LLM-based QA
> and generalize across diseases — something neither pure retrieval nor pure neural methods achieve alone.

---

## Experiment A: Rule-Augmented RAG for Biomedical QA

**Research Question:** Does injecting AMIE-discovered logical rules (with confidence scores) into
RAG context improve biomedical QA accuracy compared to plain triple retrieval?

### Steps

- [ ] **A1. Build the baseline QA system (no rules)**
  - Use existing `app.py` / `nl_to_cypher.py` as the baseline.
  - Pick a benchmark: BioASQ or a hand-curated set of 50+ Alzheimer's drug-target questions.
  - Record baseline accuracy (exact match + semantic similarity to gold answers).

- [ ] **A2. Build the rule-injection prompt template**
  - Load `outputs/discovered_rules.csv` into the RAG context.
  - Design a prompt section: `"Known Logical Rules (from graph mining): Rule 4 (99.9% confidence): IF Drug is contraindicated for X, and X shares a gene association with Disease, THEN Drug is associated with Disease."`.
  - Inject top-k relevant rules (filtered by relation types in the user's question).

- [ ] **A3. Run the rule-augmented QA system on the same benchmark**
  - Compare accuracy against the baseline from A1.
  - Log which answers changed and whether the LLM cited a rule in its reasoning.

- [ ] **A4. Ablation study**
  - Run three variants: (1) triples only, (2) rules only (no triples), (3) triples + rules.
  - Measure: accuracy, faithfulness (does the LLM hallucinate less?), and answer completeness.

- [ ] **A5. Write up results**
  - Key metric: % accuracy improvement from rule injection.
  - Key qualitative finding: examples where the LLM used a rule to answer a question it couldn't answer before.

## Experiment B: Cross-Disease Rule Transfer

**Research Question:** Do pharmacological rules discovered on one disease (Alzheimer's) generalize
to another disease (Diabetes), and can we quantify which rules are universal vs. disease-specific?

### Steps

- [ ] **B1. Complete the diabetes AMIE run**
  - Use `scripts/run_diabetes_amie.py` (already prepared, needs cluster time).
  - Parse output with `scripts/parse_amie_output.py` → `outputs/diabetes_discovered_rules.csv`.

- [ ] **B2. Align and compare rule sets**
  - Write a script to structurally compare Alzheimer's rules vs. diabetes rules.
  - For each Alzheimer's rule, check if an equivalent rule (same predicate pattern) exists in diabetes results.
  - Classify each rule as: **Universal** (found in both), **Alzheimer-specific**, or **Diabetes-specific**.

- [ ] **B3. Test Alzheimer rules on diabetes data (transfer evaluation)**
  - Take predictions generated by Alzheimer's rules and evaluate them against the diabetes subgraph.
  - Metric: What % of Alzheimer-rule predictions are actually true in the diabetes graph?
  - This directly measures rule transferability.

- [ ] **B4. Validate novel predictions against external sources**
  - Take top-k novel predictions from both disease runs.
  - Cross-reference against ClinicalTrials.gov, DrugBank, and recent PubMed literature.
  - Flag predictions that match ongoing clinical trials (strong validation) or have zero literature hits (novel hypotheses).

- [ ] **B5. Write up results**
  - Key finding: a table of universal vs. disease-specific rules with confidence scores.
  - Key claim: "X% of pharmacological rules transfer across diseases, enabling zero-shot drug repurposing hypotheses."

The Ultimate "Hybrid" Pipeline (Neuro-Symbolic AI)
If you rely only on neural networks (KGEs/GNNs), you lose AMIE's best feature: Explainability. Neural networks are black boxes. AMIE tells you exactly why it made a prediction.

Here is how you combine them into a State-of-the-Art pipeline:

Step 1: The Fast Recall Layer (The Neural Network)
You train a Knowledge Graph Embedding model (e.g., using the Python library PyKEEN or DGL). You ask it to predict the top 10,000 most likely missing links in your graph.

Pros: It's lightning-fast and catches all the fuzzy, implicit connections AMIE misses.
Cons: It occasionally hallucinates and cannot explain why it made the prediction.
Step 2: The Logic Filter (AMIE)
You take those 10,000 predictions from the neural network and feed them into AMIE. You ask AMIE: "Can you find a logical, explainable rule that supports this prediction?"

If AMIE finds a rule, the prediction is upgraded to High Confidence & Explainable.
If AMIE cannot find a rule, the prediction is marked as Speculative / Unverified.
Step 3: The LLM Validator (The "Common Sense" Layer)
You take the final list of high-confidence predictions and feed them into a Large Language Model (like GPT-4 or Gemini) via an API. You prompt it: "My graph algorithm predicts that [Method X] will solve [Task Y] because of [AMIE Rule]. Does this make scientific sense based on your training data?"

Why this is incredibly powerful:
High Recall: The neural network finds the hidden, fuzzy connections.
High Precision & Explainability: AMIE acts as a BS-detector, filtering out neural network hallucinations using hard logic.
Real-world Grounding: The LLM acts as the final human-like peer review.
If you coded this pipeline in Python (combining Neo4j + AMIE + PyKEEN + LLM API), you would have built an enterprise-grade discovery engine that rivals what top tech companies use today.
